# 敏感词与昵称校验模块 — 开发需求

> 所属：《红缘大冒险 2.0》云婚宴层
> 版本：v1.0
> 日期：2026-09-09
> 上游依据：总设计 2.0 基线 v1.1 第 4.1、6.3 节，及"个性化链接方案（自填昵称版）"讨论结论
> 执行者：Claude Code
> 边界：本需求只覆盖文本校验能力及其接入点，不涉及席位、友谊卡、留言本身的业务逻辑

## 概述

| 逻辑框架 | 预留空间 | 核心逻辑 |
| --- | --- | --- |
| 一个校验服务（服务端）＋一个校验函数（前端），共用同一份归一化规则和词库 | 词库外置为数据文件，可不改代码更新；校验字段可扩展 | 前端即时拒绝，服务端二次拒绝；命中只说"换一个"，不说命中了什么 |

**关键判断：前端校验是体验，服务端校验是安全。任何写入数据库的用户文本都必须过服务端校验，前端结果不可信。**

## 1. 覆盖范围

| 字段 | 所在页面 | 过滤 | 长度 | 备注 |
| --- | --- | --- | --- | --- |
| 宴会昵称 | 终章写名 ／ 宾客改名 | 是 | 2～12 | 全部宾客可见 |
| 公开留言 | 云婚宴留言区 | 是 | 1～100 | 全部宾客可见 |
| 友谊卡备注 | 友谊卡发起 | 是 | 0～30 | 仅互认双方可见，但仍过滤 |
| 私密祝福 | 给新人的悄悄话 | **否** | 沿用现状 | 仅新人可见，不过滤，不改动现有逻辑 |
| 敬酒问候 | 敬酒 | 否 | — | 预设句选择，无自由输入 |

长度按图形簇（grapheme cluster）计数：一个汉字、一个字母、一个 emoji 各算 1。

## 2. 组件：昵称输入框（终章 / 改名）

### 展示内容

- 输入框，占位文案："填一个朋友们认得出的名字"
- 输入框下方常驻提示："其他宾客会看到这个名字"
- 右下角字数计数 `n/12`
- 提交按钮

### 前端交互

1. 输入时即时执行前端校验（去抖 200ms）
2. 校验不通过 → 按钮置灰，输入框下方显示对应提示文案
3. 校验通过 → 按钮可点
4. 点击提交 → 调用服务端校验接口
5. 服务端通过 → 写入，进入下一步
6. 服务端拒绝 → 回到步骤 2，显示服务端返回的提示文案

### 后端数据

- 提交字段：`text`、`field`（取值 `nickname` / `comment` / `card_note`）、访客身份
- 写入前必须经过校验服务，校验通过才落库
- 改名：入席后允许改 1 次，计数字段随宾客记录保存

### 状态穷举

| 状态标签 | 触发 | 按钮 | 提示文案 |
| --- | --- | --- | --- |
| 空 | 未输入 | 灰 | 无 |
| 过短 | 图形簇 < 2 | 灰 | 再长一点 |
| 过长 | 图形簇 > 12 | 灰 | 最多 12 个字 |
| 字符不合规 | 纯符号、纯数字、含不允许字符 | 灰 | 用中文、英文或数字 |
| 保留名 | 命中保留名列表 | 灰 | 这个名字留给主角了，换一个吧 |
| 敏感词 | 命中词库 | 灰 | 换一个吧 |
| 可提交 | 全部通过 | 可点 | 无 |
| 提交中 | 已发请求 | 灰＋加载 | 无 |
| 服务端拒绝 | 接口返回 ok=false | 回到对应拒绝状态 | 按 reason 映射 |
| 网络失败 | 请求超时或断网 | 可点 | 没连上，再试一次 |
| 已用完改名次数 | 改名场景，次数为 0 | 输入框禁用 | 名字只能改一次 |

**关键判断：保留名和敏感词两种拒绝，提示文案不同，但都不告诉用户具体命中了什么。**

### 边界情况

- 粘贴超长文本：截断到 12 后再校验，不直接报错
- 输入含零宽字符、控制字符：归一化阶段剥离后再校验，不报"字符不合规"
- 首尾空格：自动去除
- 连续空格：折叠为一个

## 3. 组件：留言与友谊卡备注输入

复用第 2 节的输入组件与校验流程，差异只有长度上限和 `field` 取值。不单独设计。

## 4. 组件：校验服务（服务端）

### 接口

```
POST /api/validate-text
请求：{ text: string, field: "nickname" | "comment" | "card_note" }
响应：{ ok: true }
     | { ok: false, reason: "empty" | "too_short" | "too_long" | "charset" | "reserved" | "sensitive" }
```

- `reason` 不包含命中词、命中位置或词库信息
- 校验服务同时作为内部函数被写入接口调用，不允许绕过
- 限流：同一访客 30 次 / 分钟，超出返回 429，前端按"网络失败"处理

### 归一化流程（前后端共用同一实现）

1. 去首尾空白，折叠连续空白
   ↓
2. 剥离零宽字符、控制字符、变体选择符
   ↓
3. 全角 → 半角，大写 → 小写
   ↓
4. 繁体 → 简体
   ↓
5. 生成两份匹配文本：
   - A：仅剥离上述字符
   - B：在 A 基础上再剥离全部标点、空格、emoji（用于抓"傻·逼""S B"这类插入变体）
   ↓
6. 保留名匹配：对 A 做**完全相等**匹配（大小写不敏感）
   ↓
7. 敏感词匹配：对 A 和 B 分别做**包含**匹配
   ↓
8. 高危词拼音匹配：对 B 转拼音（无声调、连写），与高危词拼音表做包含匹配
   ↓
9. 任一命中 → 返回对应 reason；全部通过 → ok

**关键判断：拼音匹配只对高危词表启用，不对全量词库启用，否则误伤率不可接受。**

不做：同音字替换检测、语义判断、图片文字。

### 匹配算法

词库数量在数千级，要求单次校验 < 10ms。Claude Code 自行选择实现（AC 自动机或 Trie 均可），要求前端包体增量 < 100KB（gzip 后）。

## 5. 组件：词库

### 文件结构

```
data/sensitive/
  base.txt          开源词库打底（一行一词）
  custom.txt        自建补充（一行一词）
  high_risk.txt     高危词（启用拼音匹配，一行一词）
  whitelist.txt     白名单（命中也放行，一行一词）
  reserved.txt      保留名（完全匹配拒绝，一行一词）
  README.md         来源、许可证、更新方式
```

- 四个 txt 由构建脚本合并为一份运行时结构，前端和服务端加载同一份产物
- 更新词库不需要改代码，改 txt 重新构建即可

### 词库来源

- `base.txt`：Claude Code 选一份许可证允许商用或个人使用的开源中文敏感词库，**在 README 写明来源和许可证，等待阿鱼确认后再合入**
- 合入前 Claude Code 先跑一遍误伤检查：用 100 个常见友好昵称（小可爱、阿花、大头、老王、小骚包……）测试，列出误拒的词，移入 `whitelist.txt` 或从 `base.txt` 删除，清单交阿鱼过目
- `custom.txt`、`high_risk.txt` 初始为空或少量示例，由阿鱼填
- `whitelist.txt` 优先级最高：命中白名单直接放行，不再走后续匹配

### 保留名初始内容

```
阿鱼
toretto
terotto
阿晓
新郎
新娘
```

双方家人的名字与称呼由阿鱼另行提供后追加。**保留名列表本身不进前端包，只在服务端匹配**——前端对保留名的即时提示改为提交后由服务端返回，避免把家人名字暴露在前端代码里。

因此第 2 节状态表中"保留名"状态只在服务端拒绝后出现，前端不预判。

## 6. 组件：新人后台处理

第一版不做界面，提供脚本或受保护的接口即可：

| 操作 | 说明 |
| --- | --- |
| 列出所有昵称 | 输出宾客 ID、昵称、入席时间 |
| 改昵称 | 按宾客 ID 直接改，绕过改名次数限制，但仍过校验 |
| 隐藏宾客 | 该宾客不在宴会中显示，席位保留，记录不删 |
| 回扫 | 对全部已有昵称、公开留言重新跑校验，输出命中清单，**不自动修改** |

回扫命中的记录由阿鱼逐条决定，脚本不代替决定。

## 7. 分支结果对比

| 场景 | 前端 | 后端 |
| --- | --- | --- |
| 前端通过、服务端通过 | 进入下一步 | 落库 |
| 前端通过、服务端拒绝 | 显示 reason 对应文案，停留在输入页 | 不落库，记录一次拒绝日志（不含文本内容，只含 reason 和访客 ID） |
| 前端拒绝 | 不发请求 | 无 |
| 绕过前端直接调接口 | — | 同"服务端拒绝"，429 或 reason |
| 校验服务异常 | 显示"没连上，再试一次" | 返回 5xx，**不放行** |

**关键判断：校验服务不可用时宁可让用户等，不能默认放行。**

## 8. 老数据处理

- 上线时对现有昵称、公开留言执行一次第 6 节的回扫，命中清单交阿鱼
- 现有私密祝福不扫
- 回扫不改变任何数据

## 9. 验收标准

- 前端与服务端对同一批 200 条测试文本（含正常昵称、明显敏感词、插符号变体、繁体变体、全角变体、拼音高危词、零宽字符、超长粘贴）判定结果一致
- 100 条常见友好昵称误拒 ≤ 3 条，且已进白名单
- 直接调接口绕过前端，敏感文本不能落库
- 校验服务停机时，写入接口不放行
- 拒绝响应中不含任何词库内容
- 保留名不出现在前端包中
- 单次校验服务端 < 10ms，前端包增量 < 100KB gzip
- 真机微信内输入、粘贴、emoji 计数正常

## 10. V2 迭代

- 新人后台界面（列表、改名、隐藏）
- 举报按钮：宾客可标记他人昵称或留言，进入新人待处理列表

## 11. 不做

- 私密祝福过滤
- 同音字、谐音语义判断
- 自动替换为星号
- 图片或语音内容审核
- 第三方内容安全 API（引入外部依赖与费用，与项目规模不匹配）
