## 一、一条线怎么串起来

整个游戏只有一条主线，靠三样东西串起来。

### 1. 同一封请柬（贯穿回忆篇，在婚宴篇交到玩家手里）
v1.8 第 11 节：每章给请柬添一部分，而且直接改变画面，不发奖励卡。

| 章 | 材料 | 请柬的变化 |
| --- | --- | --- |
| 上海 | 钢笔 | 光标变笔尖，第一笔落下 |
| 成都 | 墨水 | 已写的线条染上墨色 |
| 来电 | 信纸 | 电话波形铺成正文纸面 |
| 静冈/静安 | 印章 | 留下第四部分的印记 |
| 海南 | 火漆 | 暖光凝成火漆 |
| 香港 | 信封 | 邮件折成信封，六部分归位 |

终章由玩家写上自己的名字、装封、盖火漆。进婚宴时，请柬就是玩家的「入场券」。

### 2. 上一章的东西变成下一章的入口（v1.8 第 4.2 节）
- 书写线 → 上海道路
- 「你好~」的光标 → 钢笔
- 墨迹 → 成都
- 同一部手机 → 来电
- 电话波形 → 信纸 → 静冈海面
- 印章圆形 → 套圈
- 最后一朵烟花 → 火漆
- 邮件 → 信封 → 回到请柬

全程不出现领奖页、结算页、选章页。

### 3. 同一份存档（`user://hongyuan_save.json`）
现在的存档结构已经有 `chapterId / nodeId / invitation`。在这个基础上加三个字段：
- `context`：表示现在处在哪一层，取值 `invitation`（请柬层）、`memoryAyu`（回忆里扮演阿鱼）、`guest`（玩家本人）、`settler`（入住以后）
- `guest`：玩家的名字、形象、席位
- `settle`：是否已入住、住处

婚宴和村子各自已经有存档，以后改成从这一份读写，三篇共用一套进度。

**身份的切换**（v1.8 第 3.1 节、故事提纲 4.4）：
- 序章：玩家是屏幕外收到邀请的朋友
- 六章：玩家扮演阿鱼
- 终章：玩家恢复自己的身份，写下名字、选形象
- 婚宴、定居：玩家以自己的形象出现

### 每章过关标准（各章通用）
- 关系推进了什么、玩家亲手做了什么、请柬怎么变、什么东西引出下一章：四样都要在画面上看得出来（v1.8 第 4.1 节）。
- 同一个人物在同一个镜头里只出现一次；说话时输入冻结；文字只出现在四个文字槽里（v1.9 第 5 节）。
- 退出后，从上表的「存档节点」继续；材料不会重复发。

## 三、婚宴和定居的最小衔接（新增）

### 婚宴：复用现有工程，只做三处接口
1. **进场**：终章点「入席」后，直接切到罗曼山庄迎宾院。跳过婚宴原有的「填昵称、选形象」，因为终章已经做过。玩家的名字和形象从共用存档里读。
2. **签到**：签到时出示请柬（显示一张完成的请柬缩略图），不新增对白。
3. **离场**：现在大门的台词是「镇上的路还没修好 下次带你去」。这句要改成通往定居篇的出口，**新台词需要阿鱼给**（第五节第 3 题）。在她给出之前，大门只显示一个「回家」按钮，不配台词。

婚宴里的后厨、湖边、果园等灰盒区域首发不开放。

### 定居：复用村子现有的入驻流程
1. 出了山庄进村，入口位置在村口。
2. 林伯办入住 → 选址 → 开第一块地，全部沿用村子现有逻辑（`test_core.gd` 87 项已通过）。
3. 阿鱼家照样能去串门，用的是冻结的成品。
4. 首发只开放：阿鱼家、4 处机构、5 户合格人家。其他房门显示「今天家里没人」。
5. 村子 95 分任务里的画面重做、14 户交互、25 个玩法，都不做。

### 存档合并
- 婚宴（`cloud.gd`、悄悄话 `user://whispers.json`）和村子（`core/state.gd`）原本各存各的。W3 时加一个适配层：读写都经过 `hongyuan_save.json` 的 `guest`、`settle` 字段。各模块的内部存档先不改。
