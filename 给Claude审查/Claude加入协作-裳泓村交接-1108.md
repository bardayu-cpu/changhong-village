## 第一件工作：村路 → 院坝 → 门 → 进出屋

1. **先认领。** 在 GitHub 任务单回复：当前基线、建议选哪一户、看到的具体根因、预计涉及文件、需要 C2/C4 配合的事、打算怎样实测。优先复核阿鱼家主门一带的现状，利用已修好的通路验证画面与通行能否对齐；若选其他户，说明为什么。以同一个实际镜头为样板。
2. **再交候选。** 让硬化地面、院坝、小径与台阶连续。草有疏密和留白，门槛、墙根和接地阴影自然，门前可见路线与碰撞一致。优先用现有合格素材及局部衔接；不要用一张矩形贴图盖住问题，也不要为样板重画房体。远山保留峨眉山轮廓；小河沿边、无桥，样板不改村庄总体格局。
3. **用实际游戏验收。** C3 用正常输入沿村路走到门前，进屋、退出再走回村路；查穿墙、错误遮挡、出门弹回。记录 13:00 的同机位画面，对照已认可参考与阿鱼家，至少检查常见横屏及窄屏是否露缝、遮挡或裁掉操作区。脚本、哈希或单块素材预览只能辅助定位。没有独立实测就标未验。首段未过前不推广全村；同一问题最多试三次，仍不过就写原因与停点。

## 交付方式

- GitHub 任务单登记认领、方案、候选 PR 和验收结果。回复简短，写清提交、实际测试、已知缺口与证据路径。测试报告放 `回执/`。同一张截图不要在多个副本里反复提交；报告输出后按用户要求清理结束测试的临时副本和历史截图。保留源素材、正式交付、报告和用户存档。
- 不上传安装包、PCK、真实存档、缓存、私钥、密码或 token。需要访问私库时，由阿鱼使用已授权的 Claude 会话连接；不要把凭证写入任务单。没有可用环境就说明阻断和可继续的只读工作。
- 第一轮回执只需四项：**我认领的范围｜候选或 PR｜C3 的结果｜还需要谁做什么**。
