## 有限静态核对

- 双存档参数各恰好一个、绝对规范路径、固定文件名、同一32位hex token目录且目录自身非符号链接；create 要求目录无文件，reopen 要求本轮 handoff 和两类存档存在。root 注入的是稳定隔离测试身份；Home.load_journal 在身份非空时不回退读写真实本地 profile，Life.open / State.open 使用显式隔离路径。所读代码路径未见真实玩家存档读写。
- 实例为 `Home.new()` 并等待 bootstrapped，使用生产 `go` 寻路及场景转换。玩法调用正常 begin / step / collect，关闭经 Interface.close / game.cancel，checkpoint 经正常 state.act。未见测试直接写位置、库存、进度或时钟以凑通过；handoff 只存实际结果供下一进程比较。
- reopen 在任何继续 go 前核实际 Home.area、实际 player.position（距离小于0.01）及竹材仍为起始值加1，然后以原收取 run 调正常 `institution_complete`，核拒绝且竹材不增加，再核可继续行走并进入村委。不同于仅 State.open 或 Host 夹具，它覆盖实际 Home 恢复及恢复后的生产寻路。
- 脚本自身只保证原 PID 与当前 PID 不同，不能独立证明前进程已退出；退出再启动的依据来自 C2 外层执行记录说明。防重断言本身不限定 message；本次 C2 输出的实际拒绝原因与生产已收取分支一致，且原 run 非空、竹材未增加，足以支持本批有限结论。
- JSON profile 守卫已改为键数及逐字段比对，保留 id / openid / nick / avatar / token / folder / ready / PID 校验。首次 reopen 在 Home 实例化前误拒不构成生产流程失败，失败记录仍保留。
