## 2. 画面方案与素材契约

### 2.1 唯一画面方向

沿用认可参考的四川现代农村聚居感：低对比短草、土路与院坝、自然弯岸、小面积芦苇和石阶、远处低饱和峨眉长脊。房屋和已定布局不重排。先做东侧北段一屏，路、草、岸、水、林带和峨眉远景同时可见；不先画新的整村效果图。

人物当前 64×84 原生帧在世界中按 1:1 绘制，`home.gd:layout_world` 的正常 `view_scale=2` 再统一放大。**定案：1 纹理像素 = 1 世界单位；正常视图 = 2 游戏渲染像素。**64×64 tile 覆盖 64×64 世界区域，32×32 tile 覆盖 32×32，不能单独再放大。任务书中的“倍率 2.0”按实际绘制链落实，以与冻结人物颗粒一致为准；不宣称所有Retina物理屏幕上均恒为2像素。

完整缩放链：禁用现有540×960基准上的`canvas_items/expand`根拉伸，Window采用`content_scale_mode=DISABLED`、`content_scale_factor=1`；Home/UI按实际游戏视口重排，世界只乘一次整数`view_scale`。540×960和1280×720均指实际游戏渲染缓冲尺寸，OS外框另记。Web的canvas backing和CSS显示区域同尺寸、浏览器100%缩放，不再用CSS transform或DPR先放大游戏再缩回；记录backing/client/DPR。逻辑游戏宽上限1280，更宽窗口保持逻辑画布居中留边，UI与输入坐标同源。改动入口为`project.godot`、`phone_boot.gd`根容器/导出Web壳及`Home.layout_world`。G0逐尺寸检查实际渲染缓冲、根倍率、世界倍率及人物/地表颗粒，不能靠单独缩放人物或图块补偿。

最近邻采样，无 mipmap、无插值缩放；平移落整数像素。镜头用正常倍率 2；既有缩放入口只允许整数 1/2。远景层使用同一屏幕像素网格，视差偏移取整，不能经过两次镜头缩放。原生 1254 大纹理不得缩小后继续充当新地表。

### 2.2 图块清单

以下尺寸均为真实源像素，不是缩图后的声明尺寸。G0 只交夏季必需格；G1 才制作其他季节。图集按需分批，不为填满大画布生成额外素材。

| 素材 | 原生规格 | 接法与变化 |
| --- | --- | --- |
| 短草 | 每季 256×64，4 个 64×64 变体 | 低对比地表，不能把高草铺满；同格索引跨季共用 |
| 土路 | 256×64，4 个 64×64 变体 | 压实土与少量细石，同尺度无强亮斑 |
| 路肩 | 256×256，16 个 64×64 邻接格 | 稀草、露土、直段和内外角；依现有道路边界拼接 |
| 院坝石 | 256×64，4 个 64×64 变体 | 与土路同尺度，门口可自然过渡 |
| 河岸 | 256×256，最多16个64×64过渡格 | 连续岸线的草泥、泥浅水、浅深水过渡；不是64格岸线自动拼接，不改变几何 |
| 浅水、深水 | 各 256×64，4 帧 64×64 | 细小水纹，4 帧离散播放，共用边界与时序，不拉伸大波纹 |
| 稻田 | 每季 256×64，4 格 | 田块几何不变；春嫩苗露水、夏绿稻、秋金穗/收割痕、冬留茬薄霜 |
| 芦苇、碎石、洗衣石阶 | 256×128，最多 8 个 64×64 RGBA 格 | 只用少量，避免重复花团；装饰物给脚点和碰撞范围 |
| 峨眉远/中层 | RGBA 1536×192、1536×160 | 从指定 `emei.png` 提取轮廓依据，金顶平顶长脊，2～3 层灰蓝雾色；完整构图只裁切、不平铺、不缩放 |
| 林带 | RGBA 1024×128 | 与远山作为同套构图，起伏轮廓遮住山脚，横向接缝自然 |
| 雾层 | RGBA 1024×64 | 允许雾的半透明；不能用纯色大矩形抹掉地面 |

相连的地表/岸线格必须画到邻接边，不能为每格留下透明缝；仅独立装饰保留 2 像素透明安全边。每批交清单：来源、原图、整数裁切区域、季节、锚点、世界尺寸、平铺/动画方式、SHA。C2 只做导入、无缩放裁切与接入，不能替 C4 用程序噪点画地面。

山体是一套完整的峨眉构图，远层与中层均禁止横向重复平铺，不能出现重复金顶；只有林带与雾可横向平铺，并检查3×1接缝。素材宽度必须覆盖既定视口与视差范围，超出已定义范围先修订契约，不能临时拉伸。水面四帧使用全局同步帧序，每一帧各自通过边缘连续检查。

远景覆盖公式为`源宽 ≥ 最大逻辑视口宽 / 最小世界倍率 + 2×最大源像素偏移`。本轮锁定逻辑宽≤1280、倍率1或2、各山层偏移≤±128源像素，故1536源宽覆盖最坏情况1280/1+256。竖屏安全构图须保留金顶长脊，不机械裁掉主峰。

岸线沿冻结连续多边形，以1世界像素精度的覆盖/距岸遮罩叠C4原生材质，地面始终有连续底材；不改成64格量化的8邻域自动铺岸，故不扩画47格。G0只交实际用到的底材和过渡格，余格待G1需要才补。遮罩仅负责边界覆盖，不生成纹理；自然度由实际镜头判断，不能以索引数量或脚本通过代替。

ImageGen 不能保证直接产出 64×64：C4 使用固定网格的大画布，目标格实际为 64×64，保持输出画布尺寸，只按整数坐标裁切、不缩放。检查边缘污染、抗锯齿、半透明杂边及 3×3 平铺，视觉不出现十字缝或亮度跳变；地表只保留明确像素笔触，雾层除外。检查失败的素材不得接入。若三次仍不能得到合格原生格，停止该素材并把实际限制交 Claude，不能用大图缩小、滤镜或程序噪点冒充。现阶段不假定存在可用的手工像素编辑管线。

原生地表的最后一次方法改为**单材质满幅生成**：每张1536×1024只画一种顶视材质，不再同图混放草、土、水、过渡及装饰，不画分格线；纯地表画布不透明。源图笔触仍按真实1像素网格设计，草叶/细石只占少量原生像素，不能画大物体再缩小。生成前固定四个64裁切区为`[704,448,64,64]`、`[768,448,64,64]`、`[704,512,64,64]`、`[768,512,64,64]`；输出后不挪区域、不缩放、不加滤镜、不重新量化像素。四格只取原图对应像素，不把整图内容压进小格。源图尺寸错误、固定区域不符该材质、颗粒不合或3×3重复可见接缝即失败。合格的小格再由C2按原有规格打包成图集，原始来源与坐标全保留。

第3次先只做一张低对比短草源图；C4自检及C3独立素材预检都通过后，才按相同预登记原则做其余地表材质。任何后续材质失败仍属于这最后一次G0-NATIVE，不拆分层数重开次数。过渡和独立装饰各自单独生成并在调用前登记最终原生覆盖区域，不与纯材质混在一张图；最终规格及连续岸线接法不改。素材预检仍不能代替G0实际镜头。

远山、山脊、林带、雾改为每层分别在1536×1024画布上生成一张独立RGBA，不再要求同一张生成图自动拆出四层。每次生成前登记固定裁切带：山层分别为1536×192/160，林带1024×128、雾1024×64，仍保持原生像素与最终规格。主峰、山脊和树冠须完整落在预定带内，带外透明；山脚基底须按设计隐藏或自然过渡，不能靠硬裁主体补救。只有源图合规才裁切，禁止拉伸或尺寸不合格时批量输出“成品”小图。各层预先声明透明/平铺边界，合格层保留，不因其他层失败而重画；整个G0-NATIVE问题次数不按层另开或清零。

### 2.3 第 0 步构图示意

方案阶段按用户“不画图”要求，仅用文字块说明分层；这不是待验收美术，也不是游戏占位图。

```text
北缘可见时：  天空 / 低对比峨眉平顶长脊      [背景视差]
               中层蓝灰山脊 / 薄雾          [背景视差]
             起伏林带与山脚遮挡             [世界前缘遮挡]
可行走平面：短草 ─ 稀草路肩 ─ 土路 ─ 草泥坡 ─ 浅水 ─ 深水
                                          芦苇/石阶    东界河
人物与房屋：沿同一俯视地面脚点排序；不进入河面或山脚。
```

山只在村北缘的可见范围出现，向南走逐步退出，不跟随玩家成为贴地海报。C2 在 `layout_world` 提供实际镜头范围，独立远景层按该范围裁切，由起伏林带和雾遮脚；世界地面不能再绘制旧 `mountain_rect`。横竖屏扩展视野时继续显示同一空间，不拉伸山景来填满屏幕。

东河保留大位置，只调整岸线的局部自然弯曲；地面、坡岸、浅/深水共享同一岸界。可行走终点和湿边阻挡吻合，装饰不能掩盖错误碰撞。路网形状保持，材质遮罩只负责衔接，不扩宽道路覆盖田块。

### 2.4 整村与四季

G0 过后，用同一材质和接法覆盖全村；取消旧世界山图、旧穿村水带、村内桥层和程序泥土 fallback。四季只换对应原生格、植被和已有天气参数；道路、田块、河岸和房位几何共用，冬季不能回到旧烘焙底图。春天嫩绿、夏天深绿、秋天金黄与暖褐、冬天枯草/薄霜必须在同机位直接辨认。

天气沿用既有全视口体系，验证 540×960 和 1280×720、调整大小后的雨雪覆盖；室内仍按既有窗外天气表现。不能用统一滤色覆盖整个画面来替代植物季节变化。
