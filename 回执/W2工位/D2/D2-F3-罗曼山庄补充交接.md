## 接入点与验收

1. `godot/hongyuan/tools/make_chapters.py` 的终章 `G-WEDDING` 目标目前是 `None`，因此点击会走下一拍 `seat.gd`。用已有场景跳转机制接山庄，进入原来的入庄流程（前门 → 喷泉 → 停车场 → 迎宾院 → 宴会厅）。山庄的 `main.tscn` 默认仍会进旧标题页，接入时应把请柬的 `guest.name`、`guest.look` 交给山庄，再调用原入庄流程，避免重复登记。改生成脚本后同步 `chapters/finale.json`。
2. 检查 Web / 微信导出实际包含山庄场景、地图和动态加载资源。原 V1.0.1.3 微信整包记录为 20,044,664 字节，接入爱情篇后分别测量平台包体，沿用山庄工程已有的加载方式核对分包。
3. 用实际导出的候选从盖火漆和二选一操作，点「去婚礼现场」后看到原山庄并能进宴会厅，核对宾客姓名、形象及再次进入。按原卡保留「先去村子入住」及其去婚礼入口，入庄后提供「跳过，直接入席」。

本次完成旧工程定位、版本比对及交接。爱情篇入口改造和导出验证仍待 Claude 接手。
