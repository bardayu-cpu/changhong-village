# V1 · 罗曼山庄收尾策划方案

基准：`hongyuan-launch @ 4ae581f`。这是 P0 审定稿，提交的是现场证据、建议和分工。阿鱼和 Claude 按 [留改表](P0-留改表.md) 逐项定完后才开 P1；本 PR 只含文档和截图。

## 目标和保护线

山庄约60分，主要扣在画风、灰盒和半完成站位图。爱情篇约75分，阿鱼家最接近期望。先把山庄入口和占位区域做成能辨认的像素场景，再补房间里缺的一件小事。宴会厅入座、翻簿、敬酒、送礼、桌游与现有规则、人物站位和门的位置是验收基准。湖边、后院等已满意画面锁定，保护范围先定再接图；不因统一而整块调色或换景。

画布逐块做什么、每间拟补什么，见 [P0-留改表](P0-留改表.md)。当前基线为15个独立画布，外加后厅内化妆间取景；若批准恢复旧独立化妆间和娱乐室，要另列范围、变更后的画布数及门和存档验收。后厅的原后厨、休息室、麻将间、化妆间分别验可识别、能走近、能开始、能退出。已有玩法继续用，只有缺口才补，拟补不构成定稿。

## 画风怎么统一

- **村子定室内尺度和生活感。** 在同一版本用 `godot/ayu_home/v4/assets/approved-floor1.png` 与阿鱼家实际运行画面作参考：家具大小、人物脚底线、深色轮廓、统一光向和像素边缘。沿用村子经核定的环境密度和生活道具，房间各有一个明确可互动焦点。户外以村景同类运行画面为准，另用 `候选/整村95-G0-1026/overlay/ayu_home/v4/assets/village/g0-1026/` 的 `preview-bank.png` 与 `preview-middle.png` 分别看岸边和远山层次，候选预览不作运行验收。村子代码与素材只读。
- **爱情篇定户外色光和跨世界连续性。** 对照 `godot/hongyuan/assets/w2/shanghai/` 的入口、停车和广场同类素材，以及仓内 `godot/hongyuan/assets/w2_review/wedding_r1/` 迎宾院和广场候选；先区分运行画面与未接入小样。只借爱情篇的光色、轮廓和景深，不照搬其正面镜头；山庄保留俯视可走视角。近景可走处保留清楚的明暗边缘。婚宴保留喜庆红、木色与暖灯；远处用较弱对比，门、台阶和交互点保持可辨。
- **先锁定比例，再画分层。** V4 以现有角色身高、脚点、屋门和镜头为尺，不为背景缩放角色。参考旧版环境粗颗粒与角色细颗粒的做法，用同机位原尺寸与最近邻2倍并排，确认边缘、光向、冷暖和缩放；禁止模糊拉伸。拆底图、可遮挡家具、门牌、互动道具与人物/站位图，画面更新不改变占地与导航。
- **先出三张样板。** 建议先小卖部（校室内比例和像素颗粒），再迎宾院（校婚礼入口和人物遮挡），最后喷泉广场（校大室外景的层次）各一张，最终从获准重画的块里挑。和湖边、后院认可画面、阿鱼家、爱情篇同类画面并排；保留区只做对照。V5 审对齐及可辨识，Claude 审后请阿鱼看实图。

## 主要风险与验收

1. **旧合包整树覆盖会回退跨世界。** 复用 `f196cc3` 的独立房间素材、脚点、生成链及测试，单独移植最少必要的接口；保护当前请柬入口、右上切换、07号图、云桥与检查点。[差异与清单](P0-旧分支与本地清单.md)
2. **图对了也可能挡路。** 保留布局数据为唯一坐标源；门槛、脚底线、人物座点和遮挡按原位置走。V5 同机位前后图和出入口往返都验，先核果园 A/B 回程与前后门。
3. **跨世界或刷新可能掉状态。** 现有桥接测试未覆盖金币、小游戏进度、签到和果园。先验证独立 Web 中假云重建有无覆盖本地的情况，并记录进、出、重启三次读数。不能以截图代替存档验收。
4. **包体和运行环境。** 不把审图工具、原始图或 P0 证据塞进导出包。沿用动态资源、JSON 和 shader 包含规则；P5 在真实 Web 与目标包复测07号宾客、控制台和分包，不提前写零报错。
