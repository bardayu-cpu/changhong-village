## 一、做法

调试版日志面板顶上加了两个按钮「远程加载」「删掉本地副本」（点左上角绿字打开）。点「远程加载」：

1. 先看本机 `user://canvas/scene_roman_banquet/base.png` 有没有、大小对不对。有而且对，就直接读本地，**不下载**（第二次打开走这一路）
2. 没有：Godot 经云桥发一个 `@fetchFile` 给微信那一层（`wxgame/remote.js`），带上 File ID 和 `user://` 的绝对路径
3. 微信那一层：`wx.cloud.downloadFile` 下到临时文件 → `readFile` 读成 ArrayBuffer → `GODOTSDK.copy_to_fs(路径, 数据)` 写进 Godot 的文件系统。模板把 `/userfs`（就是 `user://`）挂成 WXMEMFS，写完关文件时同步写到微信本地文件，下次启动挂载时读回来
4. Godot 读出这个文件 → 解码 PNG → 传显卡 → 在面板上显示那张图，面板上写一行用时

每一步用时打进日志，都以「[suqi] 远程加载」开头：下载、读临时文件、写进 user://、桥来回、读本地、解码、传显卡、总共。本地副本大小不对或者解不开，就删掉重下。

名字以 `@` 开头的请求不去调云函数，交给微信那一层自己做（`cloud.js` 里加了这条转发）。只往显卡传图，不从显卡读回。

## 十、第 30 版真机：下不下来，改走云函数（9/19，提交 f70d681）

### 真机结果和原因

- 第 30 版（0919-0822）真机点「远程加载」出「下载失败：download_failed internal server error: empty download url」；心跳、存资料、小游戏都正常（01 转）
- 原因（阿鱼查实）：云开发控制台 → 存储 → 权限设置是「仅创建者可读写」。那页写着云控制台和服务端始终有所有文件的读写权限，这个设置只管小程序端发起的请求。所以阿鱼在控制台传的图，玩家读不到，`wx.cloud.downloadFile` 就回 empty download url
- 改权限要升级付费版，阿鱼暂不升级

### 「empty download url」还可能是什么（以后再遇到照这个查）

1. File ID 和控制台里的对不上：复制时少了字、多了空格或换行、路径大小写不对
2. File ID 里的环境和游戏 init 的环境不是同一个（换过环境、复制了别的环境的 File ID）
3. 文件被删了、挪了位置，或者重新传过换了 File ID
4. 存储用了自定义安全规则，规则不让读
5. 环境欠费、停用，或者流量超了【待验证：这几种会不会也报这一句】

这次别的都排除了：环境对得上（File ID 和 `wxgame/cloud.js` 都是 cloud1-d9ggg36tj34742bef），别的云函数都通，03 核过 File ID（第九节）。

### 加了诊断（小程序自己下那条路失败时）

- `wxgame/remote.js`：`wx.cloud.downloadFile` 失败，或者成功了却没有临时文件，就顺手问一次 `wx.cloud.getTempFileURL`，带回：
  - 它回的 status、errMsg
  - File ID 里写的环境、游戏 init 的环境
  - File ID 多长、有没有空白换行
  - 开发版、体验版还是正式版
- `scripts/remote_probe.gd` 翻成一句人话，日志和调试面板上都有，截图就看得出是哪种：
  - 没权限（STORAGE_EXCEED_AUTHORITY）
  - 文件不在（STORAGE_FILE_NONEXIST）
  - 两边的环境对不上
  - 临时链接拿得到（那就是下载那一步的事）
- 临时链接 8 秒不回也照样把下载失败交回去，不会卡住

### 几条路比一比

| 路 | 要配下载域名吗 | 免费版能用吗 | 一次多大 | 开发版、体验版、正式版 | 结论 |

### ⚠️ 第 1 条安全检查：`%2e%2e`（URL 编码的 `..`）能绕过 `canReadCanvas`，部署前必须处理

01 点名要重点打的这条，结果是：**`canReadCanvas` 本身对 URL 编码不设防**。直接跑：

```
canReadCanvas('cloud://env.bucket/canvas/%2e%2e/secret.png')   → true（放行了）
canReadCanvas('cloud://env.bucket/canvas/%2e%2e%2f%2e%2e/secret.png') → true（放行了）
```

原因：`src/canvas.js` 的检查只找字面的两个字符 `..`，不会先做 URL 解码再查。`%2e%2e` 解码后就是 `..`，但作为原始字符串它不含 `..` 这两个字符，也不含空白，`canvas/` 前缀又天然满足，于是被放行，交给 `cloud.downloadFile({fileID})` 去处理。

**这个口子能不能真的读到 `canvas/` 外面的文件，取决于微信 `wx-server-sdk` 的 `downloadFile` 会不会对 File ID 里的 `%2e%2e` 做解码/归一化——这一点我没有办法在这台电脑上验证**（没有真实云存储环境，`cf-mock.test.js` 用的是内存里的假实现，不会复现腾讯云存储后端的真实解析行为）。File ID 通常是腾讯生成的一串不透明字符串，人工拼出一个带 `%2e%2e` 的 File ID 能不能被后端认成合法路径、会不会被解码，文档里没查到明确说法。

**不管后端会不会解码，这个口子都不该留着**：
- 修法很简单：`canReadCanvas` 在查 `..` 之前先对整个字符串做一次 `decodeURIComponent`（要包一层 try/catch，解码失败就直接拒），或者更严格地，只要发现字符串里出现 `%` 就直接拒绝（File ID 正常情况下不会出现 `%`）
- 这是纯函数层面的加固，改完把 `test/rules.test.js` 或者 `test/cf-mock.test.js` 里补上这几条 `%2e%2e` 用例，钉住不再回退

**除了这条，我自己又试了一圈 01 点名要试的绕法，都挡住了**（写了个独立脚本 `node -e`，不是照抄 `cf-mock.test.js` 里已有的用例）：

| 绕法 | 结果 |
| --- | --- |
| 大小写（`CANVAS/`、`CLOUD://`） | 挡住 |
| 前面多加斜杠（`//canvas/`） | 挡住 |
| 深层伪装＋`..`（`notcanvas/canvas/../../secret`） | 挡住 |
| 前缀伪装（`canvasXXX/`不是`canvas/`） | 挡住 |
| 空格、tab、换行 | 挡住 |
| 空字符注入（`canvas\0/`） | 挡住 |
| 缺 env.bucket 部分（`cloud://canvas/x.png`） | 挡住 |
| 不是 `cloud://` 开头 | 挡住 |
| 空字符串、`null`、数字 | 挡住 |
| 超长路径（500万字符文件名） | 放行（不是安全问题：只是字符串长，处理耗时 3 毫秒可忽略；真去查存储会因为没有这个文件而 `download_failed`，不会造成越权或者卡死） |
| 单点 `.`、`#fragment`、`?query=` | 放行（对象存储的 key 是字面字符串比对，不是文件系统路径，`.`/`#`/`?` 不会被当成路径语法解析，放行了也只是查不到匹配的文件，不构成越权——这几个我判断风险低，跟 `%2e%2e` 性质不一样，`%2e%2e` 是"看起来像被过滤了、实际可能被下游解码"，这几个是"字面上就查不到东西"） |
| offset 负数、超大、小数、`NaN`、`Infinity`、字符串、`null` | 全部 `bad_request`（`chunkRange` 用 `Number.isInteger` 卡得很严） |

软链接式路径这条不适用：对象存储没有文件系统意义上的软链接，File ID 就是一个字符串键，不存在"链接到别处"这回事。

**建议**：`%2e%2e` 这条按上面说的加一道解码后再查（或者更简单粗暴：直接拒绝含 `%` 的 File ID），这条不过，这次先别部署——跟 01 说的"这条过不了我就不部署"对齐。别的检查我没发现能绕过的口子。
