## 三、**这一轮最贵的教训：验素材不能只看数**

9/21 我把 GPT 交的乐队图接进去，用的验法是「每块图拿去和阿鱼确认的效果图逐像素比色差」，**八块全是 0.0**，我当成验过了。

**9/22 阿鱼真机一看就打回：「你的图都扣烂了」。**

**盲点在这儿**：抠出来的图粘着原图的背景时，把它贴回原图当然严丝合缝。**0.0 只证明「是从这张图上拆的」，证明不了「拆干净了」。** 实际上三个乐手身上挂着成块的红地毯和墙，**有一个人的脸被一块墙顶掉了**，三个音符是碎片加一截墙。

阿鱼问「为什么不让 03 测出来」——**03 也测不出来**。它跑无界面逻辑测试，能测图摆没摆上、坐标对不对、挡不挡人，测不出「脸被墙顶掉了」。

**所以**：`tools/check_blocks.py` 是必过的一关，**每批素材进项目前先跑**：

```
python3 tools/check_blocks.py <图所在目录> [输出png]
```

它把每块画在白底和深底上排成一张总览图，外加背景残留／破洞／半透明边三项粗测。
**粗测只是提示**——乐队那次它只报出两张，脸被顶掉那张它报「干净」；9/23 作物图那次它报了一堆「破洞」，全是叶子缝的误报。
**最后一定要拿眼睛看那张总览图。** 这一步归 02，别跳。

## 六、最容易踩的坑

1. **验素材只看数会栽**——见第三节
2. **导出用 zsh 不用 bash**
3. **提交带路径**（`git commit -m … -- <路径>`）
4. **跑导入别套 `script -q /dev/null`**：9/23 那样跑，`.import` 一个都没生成、还不报错，接着测就是「图明明在却用不上」。直接跑：`Godot --headless --editor --quit-after 300 --path .`
5. **新 worktree 先跑一遍导入再测**，不然报假「不行」
6. **GDScript**：`var x := 没类型的引用.方法()` 推不出类型会编译挂，写成 `var x: int = …`；`int(null)` 报错；**json 里的数字读进来是小数**（`12 in [12.0]` 是 false）；`get_image()` 微信里禁用
7. **界面的 `sync()` 要在 `main._process` 里叫**
8. **测试里拨时间用真实纪元量级**（1_789_876_799 这种），小数字往回拨会成负数
9. **包体两种量法别混**：历史记的是开发者工具报的数（主包 108.5 KB），`du` 量出来是 163.9 KB（多算了 `images/` 那 56 KB）。**照工具的数记**
10. **别碰 `../wechat-build` 手改**，导出脚本会写它
