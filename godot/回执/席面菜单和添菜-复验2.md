## 1. 时区固定 UTC+8（过）

- 做法读代码确认：`banquet_menu.gd` 的 `hour_now()` 用 `Time.get_unix_time_from_system()`（UTC 纪元秒）加 `utc_offset_hours`（`menu.json`，值 8）× 3600，再 `get_datetime_dict_from_unix_time` 取小时；不读设备时区
- **同一批真实瞬间，五个时区各跑一遍，全部一样**（`TZ` = Asia/Shanghai、UTC、America/New_York、Asia/Tokyo，外加 Australia/Sydney）。11 个瞬间（都用真实纪元量级）：

| 北京时间 | 该是 | 五个 TZ 都算成 |
| --- | --- | --- |
| 2026-09-20 11:59:59（含 11:59:59.9） | 11 点 晚宴 | 一致 |
| 12:00:00（含 12:00:00.9） | 12 点 正席 | 一致 |
| 17:59:59 | 17 点 正席 | 一致 |
| 18:00:00 | 18 点 晚宴 | 一致 |
| 23:59:59 → 次日 00:00:00 | 23 点、0 点 都是晚宴，没有空当 | 一致 |
| 2026-09-20 00:00:00 | 0 点 晚宴 | 一致 |
| 2099-01-01 11:59:59 / 12:00:00 | 晚宴 / 正席（绝对值跳到 2099 不溢出） | 一致 |

- **真实时钟那一支**（不拨 `fake_now`）：五个 TZ 下算出的钟点都等于北京时间的钟点（当时 17 点）
- `test_banquet_menu` 在四个 TZ（Shanghai / UTC / New_York / Tokyo）下各跑一遍，**全 PASS**
- `fake_now` 的哨兵是 `> 0.0`：0 和负数会静默退回真实时钟。代码注释已经写明「要用真实纪元的量级」，拨 2099 年没问题，记一笔

### 防回退测试「真能拦住」吗？拦得住那一种，只那一种

在一次性 worktree 里把 `banquet_menu.gd` 改坏、跑 `test_banquet_menu`，再还原：

| 改坏成什么样 | 结果 |
| --- | --- |
| 真实时钟那支读回 `Time.get_datetime_dict_from_system()`（阿鱼那条要防的回退） | **拦住了**：「源码不读设备时区」不行，三个 TZ（Shanghai / Tokyo / UTC）都 FAIL |
| 连 `fake_now` 那支一起换成读本机（`get_time_dict_from_system`，或加上 `get_time_zone_from_system` 的偏移） | 在 `TZ=Asia/Tokyo` 下拦住了（四个边界不准），但那是因为 `fake_now` 也被改坏了；偏移那种在北京时区下跑不出差别 |
| **只有真实时钟那支**读本机小时，`get_time_dict_from_system()`；`fake_now` 那支照旧 | **没拦住**：Shanghai / Tokyo / UTC 三个 TZ 整份测试都 **PASS** |

也就是：四个边界测试全走 `fake_now`，不碰真实时钟那支；那一支只靠「源码里不许出现 `get_datetime_dict_from_system`」这一个函数名守着。换成兄弟接口就漏了。不挡出码，低。
- 补的方向（02 定）：加一条「`fake_now = -1` 时 `hour_now()` 等于 `Time.get_unix_time_from_system()` 自己 +8 小时算出来的钟点」，在 `TZ=Asia/Tokyo` 那类非北京时区下跑就拦得住；或者把守卫改成「源码里不许出现任何 `_from_system`（除了 `get_unix_time_from_system`）」
