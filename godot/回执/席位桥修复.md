## 一、先说查到的：这个适配层里 JavaScriptBridge 到底支持什么

查的是导出模板那一层，也就是导出后 `wechat-build/engine/godot.js` 里的 `GodotJSWrapper`
（`addons/godot-minigame/` 只有一个编辑器插件和一个 macOS 动态库，不含运行时，桥的实现全在模板里）。

| 问的 | 查到的 | 怎么查的 |
| --- | --- | --- |
| `get_interface` 拿对象 | 支持，而且**认 GameGlobal**。它按 globalThis → GameGlobal → window 的顺序找名字 | `resolveNamedObject` 的源码 |
| 名字能不能是任意字符串 | 能。名字就是一个 C 字符串传过去的，和 `__suqiLog` 一样的路 | 同上 |
| **查一个名字会读几遍属性** | **两遍**：先 `typeof root[name]`，再 `root[name]`。这条很要紧，新桥要靠它去重 | 同上 |
| 方法能不能带参数 | 胶水层**写着支持**：`_godot_js_wrapper_object_call` 会把参数一个个转过来再 `obj[method](...args)` | godot.js 源码 |
| 返回值是什么类型 | null/bool/整数/小数/字符串/对象都能编组回去（Variant 的 0/1/2/3/4/24） | `js2variant` |
| **eval 能不能用** | **确认不能**。`godot_js_eval` 的胶水整个不存在，wasm 的导入表里也没有。`JavaScriptBridge.eval()` 在这个模板上就是死路 | 在 godot.js 里 grep 不到 `godot_js_eval`；把 `godot.wasm.br` 解开看导入表 |

**所以「带参调用」在代码上看是支持的，但真机上第 17、18 版两次都不通。**

## 二、根因（三个，互相独立）

**根因一：桥的写法没验过，而且断了没人知道。**
第 17、18 版的桥是「带参数调 JS 方法 `req(名字, 参数)` 拿编号，再 `poll(编号)` 问结果」。
这条路在电脑上根本不走——电脑上用的是内存里的假席位，所以电脑全通、真机全挂。
更糟的是：桥一断，请求发不出去，**回调永远不来**，界面上就是什么都不显示。
你看到的「五步全挂、连个提示都没有」就是这么来的，不是五个毛病，是同一个。

**根因二：换桌的字段名和服务端对不上。**（0916-1432 修，阿鱼真机第 19 版测出来的）
第 19 版桥通了——阿鱼看到了「先找把空椅子坐下」这类顶部提示，「坐这儿」也弹得出来，
说明 `enterHall` 一路都好。挂的是换桌：点确认后显示「没连上」。
真正的原因是客户端发的是 `table_id`、`chair_no`（下划线），
服务端 `changeSeat` 收的是 `tableId`、`chairNo`（驼峰），直接回 `bad_request`；
而客户端的拒绝原因表里没有 `bad_request`，兜底成了「没连上 再试一下」，把真原因盖住了。
**字段名以服务端为准，改客户端对齐，云函数一行没动。**

**根因三：金标画在底图下面。**
自己座位的小金标 `z_index` 写的是 -5，沉到底图和桌子下面。这个和桥无关，
**电脑上也看不到**，之前说的「电脑上假数据全通」在这一步上其实没通，是没人凑近看。
就算桥修好，验收第一步照样会挂。

## 三、改法

**送出去（Godot → 微信）**：请求先转成一行纯 ASCII 的 JSON（中文、表情写成 `\uXXXX`，
JS 那边 `JSON.parse` 自己还原，不用在 JS 里解 UTF-8），再一个字符一个字符当
`get_interface` 的名字查过去，换行符表示这条完了。JS 那边把 96 个可打印字符
各注册成一个带 getter 的名字，名字被查到就等于字符收到了。
名字分 A、B 两套轮流用：因为适配层查一个名字会把属性读两遍，JS 靠
「名字和上一个一样就忽略」去重，轮流用才不会把连着两个一样的字符吃掉一个。

**取回来（微信 → Godot）**：无参方法返回字符串，和日志面板读 `__suqiLog.text()` 一模一样。
`__suqiCloud.pop()` 一条条取结果，`openid()` 取自己的 id。

**不带参数调 JS 方法、不用 eval、不读显卡。** 玩法这条路上一个带参调用都没有。

**桥断了也要有反应**：读不到 `__suqiCloud` 就直接按「没连上 再试一下」回调；
另外加了 12 秒超时，请求久久不回来也按没连上处理。以后再断，你至少看得到一句话，
不会像第 17、18 版那样整个哑掉。

**金标**：`z_index` 从 -5 改成 4，画在底图和桌子上面。

**换桌字段名**（0916-1432）：`main.gd` 发请求时转成服务端要的驼峰 `tableId`、`chairNo`。
本地 `sit_target` 还是下划线（和席位数据一套），只在发出去的那一下转。
拒绝原因表补上 `bad_request`、`no_seat`，文案都用已定稿的「没连上 再试一下」（没新写文案）；
同时加了一条规矩：**没见过的原因一律打进日志**（`[suqi] 换桌 被拒，原因没见过：xxx 整条返回 …`），
不然又会像这次一样被「没连上」盖住。电脑上的假数据也跟着改成驼峰，
而且少字段就和服务端一样回 `bad_request`——这样字段名发错在电脑上就能测出来。

改的文件：`godot/wxgame/cloud.js`、`godot/scripts/cloud.gd`、`godot/scripts/layered_hall.gd`（金标一行）、
`godot/scripts/main.gd`（日志面板顺带跑一次桥自查；换桌字段名、拒绝原因表、真实原因打日志）。
设计文档、素材、云函数、server-claude 一个没动，也没加新玩法。

    翻到「上一次打开」那一段，把探针前后几行拍给我
