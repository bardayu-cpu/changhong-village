**是测试自己的写法碰运气，游戏没毛病。** 失败的永远是同一条断言：测试里 `6b`（第 9 关「只能绕左边外圈」那一对）。已改测试，改后 200 回 0 失败、20000 个种子 0 失败。

## 为什么（测试的毛病）

`6b` 要造一对只能从左边外圈绕的牌：取最左一列最上 (0,0) 那张的种类 `kk`，把最下那张 (0,R−1) 换成 `kk`——办法是去棋盘里找**另一张** `kk` 牌，跟最下那张对换。可是找的时候写的是 `for x in range(1, 列数)`，**跳过了最左一列**。第 9 关棋盘 7×7（奇数少一行，实际 7×6）、12 种牌，棋盘是每回开局随机发的（`host` 给 `rng` 一个随机种子）。**要是 `kk` 的另一张恰好只在最左一列**（不在最下面），就找不到可换的，没换成，后面 `tap((0,0))`、`tap(最下)` 点的是两张不同种类的牌，连不上，没有连线 → `line == null` → 「绕左边外圈 false、连线全在游戏区里 false」。

自己验：拿同样的发牌（`LLK.make_board(7, 7, 12, rng)`，第 9 关参数 `cols 7、rows 7、kinds 12`）跑 **20000 个种子**，按测试原来的找法，换不过来的有 **296 个（1.48%）**，跟 200 回里 2 回（1%）吻合；换得过来的，`can_link` 一律连得上、一律绕左边外圈（连不上 0、没绕左边 0）。**所以游戏的连线逻辑没毛病**。

跟时间、等待不够无关：这条测试里没有等待，帧、计时都不进判断；连跑 30 回全过也是因为 1.5% 本来就难碰上。02 那回碰上的是同一条（它报错是偶发，不是机器忙）。

## 怎么改的（已改，`godot/tools/test_game_lianliankan.gd`）

找另一张 `kk` 时把最左一列也算进去，只排除 (0,0) 自己：

```gdscript
for y in b9.size():
    for x in (b9[y] as Array).size():
        if Vector2i(x, y) == Vector2i(0, 0):
            continue
        if not done_swap and int(b9[y][x]) == kk:
            ...
```

最左一列的牌被换走一张不碍事：最左一列还是满的，(0,0) 到最下那张直走、拐一个弯都不通，只剩绕左边外圈（20000 个种子里 0 个例外）。顺手把注释里「第 9 关 8x8」改成「7×7，奇数少一行变 7×6」。

改后验证：20000 个种子 0 失败；真测试连跑 200 回 0 失败。

## 要 01、02 知道的

- 游戏没改，不用 02 动。
- 这条测试只改了一处找牌的范围，别的断言没动。
- 同类提醒：测试里「随机发牌再找一张怎样的牌」要把所有位置都算上，别图省事排除一整列；同一类的随机测试可以拿 20000 个种子在一个脚本里先压一遍再进仓库。
