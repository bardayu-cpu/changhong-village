## 为什么（测试的毛病）

第 4 节「让玩家」：测试在快进 3 分钟之后，找**第一位正站着（state = stay）、离红毯中间 100 像素以上**的客人 `w0`，把玩家放到他跟前，看他有没有挪开。**要是快进到的那一刻院子里恰好没有这样的人（7 位客人都在走、让路、进门或出门），`w0` 就是空的**，后面「离玩家」按 0 算，判不过。调试输出确认：失败那回「站着的有 0 个」。游戏的让路逻辑没出错——没客人站着，根本没东西让。

**为什么每回不一样**：测试以为固定了种子（`life.reseed(7)`）就每回一样，其实不是。初始状态每回一样（我对了 80 回的初始指纹，一模一样），但快进出来的结果不一样：同一个种子 80 回，3 分钟里「从大门进来的」个数 11～15 都有（13 个 31 回、12 个 18 回、14 个 14 回、15 个 2 回、11 个 2 回……），说明走着走着分岔了。原因是 `court_life.gd` 的 `reseed` 只重新摆了走动的客人，**新娘爸妈、摄影师的小动作（greeters）没一起重置**：它们的第一次计时 `g["t"]` 是进院子 `setup` 时、种子还没定（`rng.randomize()`）抽的，之后每一步又从**同一个随机数**里抽（下一个动作隔多久、做什么）。它们抽的次数和时刻每回不同，把客人那条随机数的序列也带偏了。所以「快进 3 分钟后院子是什么样」每回不同，偶尔正好没人站着。

## 怎么改的（已改，`godot/tools/test_court_life.gd`）

找 `w0` 时，没有就再往前快进，**最多再快进 60 秒**等一位站着、离红毯远的出现；60 秒内还没有才算没过：

```gdscript
var w0 = null
for tries in 30 * 60 + 1:
    for w in present(life):
        if w.state == "stay" and w.pos.distance_to(Vector2(768, 500)) > 100:
            w0 = w
            break
    if w0 != null:
        break
    life.step(1.0 / 30.0)
```

别的断言没动（它们在 140 回里没碰上过失败）。改后连跑 **300 回 0 失败**。

## 要不要 02 改游戏

**不用改就能出码。** 顺手可以改的一件小事（01 定，不急）：`court_life.gd` 的 `reseed` 把新娘爸妈、摄影师的小动作（greeters）的计时也一起重置、或者给它们单独一个随机数，这样「固定种子快进 N 秒」才真的每回一样。现在主程序截图用 `court.settle_people(20261002, 12.0)`「按固定种子摆、快进 12 秒：每回截出来一样」，同样不是真每回一样（客人的站位可能差一点），04 拿截图前后对比的时候会碰到。
