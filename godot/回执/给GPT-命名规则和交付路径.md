## 二、叫什么

全小写、下划线分隔、**不用中文和空格**。

| 类 | 前缀 | 例 |
| --- | --- | --- |
| 底图 | `base` | `base_v1.png` |
| 可无缝铺的瓦片 | `tex_` | `tex_grass_lawn_v1.png` |
| 立在地上、**能挡住人**的积木 | `blk_` | `blk_piano_v1.png` |
| **挡在人前面**的前景 | `fg_` | `fg_railing_v1.png` |
| 小道具 | `prop_` | `prop_ball_v1.png` |
| 装饰、光效 | `decal_` | `decal_lantern_glow_v1.png` |
| 人物 | `chr_` | `chr_cellist_v1.png` |

几条硬的：

- **版本号跟这一批走**：同一块画布同一批交付，所有文件用同一个版本号。这一批统一 `_v1`
- **不覆盖已有文件。** 改版加 `_v2`，旧的留着
- **两块画布用到同一种东西但画法不同**时，名字里加场景词区分：`tex_grass_lawn_v1.png` / `tex_grass_orchard_v1.png`

## 三、交接单

**每块画布一份**，放该画布的 `交接/`，叫 `handoff_<场景 id>_<批次>_v1.json`。

例：`handoff_scene_roman_banquet_band_v1.json`、`handoff_scene_luoman_lake_blocks_v1.json`。

格式照你交得最好那一份 —— `handoff_minigames_shared_dish_tiles_v1.json`。每个文件必须写：

| 字段 | 说明 |
| --- | --- |
| 路径 | 相对该画布目录 |
| 尺寸 | 实际像素 |
| `sha256` | 我会逐条核 |
| **能不能挡住人** | 不写我就不知道该放哪一层，玩家会从钢琴中间穿过去 |
| **锚点（脚点）** | 这件东西"站在地上"的那一点，写**图片内部的像素坐标** |
| **能不能重复接** | 能的话写清往哪个方向（左右／上下） |

**外加两样，缺一样这批就不算齐：**

1. **拼接方式** —— 这些积木**怎么拼成那张效果图**：哪块铺哪片区域、哪个重复几次摆在哪（**要画布像素坐标**）、谁压在谁上面、动效从哪个点开始。
   **上一批五块画布就是卡在这儿**：57 件只有 34 条写了摆位、带像素坐标的只有 1 条、11 件一个字没提，我们按那份单子拼不出效果图，只能猜，所以按住没接。
2. **`questions` 字段** —— 拿不准的写进去，**别自己猜**。你第一批把它留空我很放心，有疑问就写进去。

**写了交接单就代表这一批齐了，我才开始接。**

## 四、格式（这部分由我定，不是画风）

- PNG 透明底，**alpha 只有 0 和 255**（不要半透明边、不要棋盘格假透明）
- **原尺寸即用**，我不放大缩小。尺寸你定，写进交接单
- **风格、比例、画法归你和阿鱼在造景台定**，我不碰

## 五、流程（别跳步）

1. **我**给你一个**场景**（里面有什么元素、每样跟玩法怎么挂钩）
2. **你**在造景台里出 **3～5 张这片场景的还原效果图**，给阿鱼选
3. **阿鱼**选定一张
4. **你**把那张**拆成积木**，按上面的路径和命名交付，带拼接方式和那张效果图
5. **我**在游戏里还原
6. **阿鱼**试玩

**别没选图就拆包。** 也**别一次做五块**——一块一块交，我一块一块接，省得一起返工。
