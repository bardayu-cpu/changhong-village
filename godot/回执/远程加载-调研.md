# 调研：画布素材远程加载（§0.9）能不能做

> 日期：2026-09-17
> 谁：助理 01 派只读调研分身查导出模板（wechat-build 里 godot-minigame 4.7 模板的 JS 胶水），助理 01 整理
> 地位：纸面结论，**还没在真机上验证**。真机最小验证排在宴会厅第 23 版之后（HANDOFF 迎宾院一节）

## 结论

| 问题 | 结论 | 依据（文件：位置） |
| --- | --- | --- |
| 游戏包 pck 怎么进引擎 | 从包内本地文件读，放进 Emscripten 内存文件系统 | `engine/game.js`：`GODOTSDK.startGame('/engine/godot', '/engine/demo-pck.bin')`；`godot-sdk.js` 的 `fsUtils.localFetch` 用 `wx.getFileSystemManager().readFile` |
| JS 能不能在运行时往 Godot 的文件系统里写文件 | **能**，有现成入口 | `godot-sdk.js`：`GODOTSDK.copy_to_fs(path, arrayBuffer)` → `engine.rtenv.copyToFS` → `FS.writeFile`（`godot.js` 的 `Engine.prototype.copyToFS`，Godot 官方公开接口）。要等引擎启动完（`rtenv` 不为空）才能调 |
| `user://` 存在哪，关掉小游戏再开还在不在 | **在**。模板自己做了 `WXMEMFS`，挂在 `/userfs`（Godot 网页版的 `user://` 就是这里），每次写、删、建目录都同步写到微信本地文件 `wx.env.USER_DATA_PATH`，启动挂载时读回 | `godot.js`：`GodotFS.init` 里 `FS.mount(WXMEMFS, {}, path)`；`WXMEMFS` 的 write、mkdir、rename、unlink 调 `wx.getFileSystemManager()` 的同步接口 |
| Godot 的 HTTPRequest 走什么 | `wx.request`（要在小游戏后台配合法域名），不认云存储的 fileID | `godot.js`：`GodotFetch.create` 直接调 `wx.request({... responseType: "arraybuffer", enableChunked: true})`；三个引擎文件里 `wx.cloud` 出现 0 次 |
| 图片字节能不能在 GDScript 里解码 | 看不出（解码在 wasm 里，胶水层没有证据），要真机验 | — |

## 推荐的路

1. JS（照 `wxgame/cloud.js` 的写法）：`wx.cloud.downloadFile({fileID})` 下载云存储里的图，不用配域名
2. `wx.getFileSystemManager().readFile` 读成 ArrayBuffer
3. `GODOTSDK.copy_to_fs("/userfs/canvas/<画布>/<文件>", buffer)` 写进 Godot 的 `user://`；因为 `/userfs` 会同步落盘，第二次打开不用重下
4. JS 把「哪个文件好了」放进结果队列；Godot 照现在的桥用无参方法 `pop()` 取（不能直接把 ArrayBuffer 交给 Godot，桥只传字符串）
5. GDScript：`Image.load_from_file("user://canvas/...")` 或 `FileAccess` 读字节再 `Image.load_png_from_buffer`，再 `ImageTexture.create_from_image`（往显卡传图可以，禁的是从显卡读回）

注意：JS 在引擎启动后直接往 `USER_DATA_PATH` 写文件，Godot 这次运行看不到（只在挂载时读回一次），所以一定走 `copy_to_fs`。

## 真机最小验证要看的

- `copy_to_fs` 能不能调、写进去 Godot 马上读得到
- PNG、JPG、WebP 哪几种在 wasm 里能解
- 杀掉小游戏重开，`user://` 里的文件还在，不重下
- 一张 1～2MB 底图从下载到显示要多久，卡不卡帧
- 微信本地文件空间上限（待验证）
- 往云存储上传图片要先问阿鱼（§0.6）
