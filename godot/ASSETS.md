## 协作边界

- 分工：GPT 负责和 Godot 配合的三样：出图、文案、交互场景配置。游戏代码、服务端、导出微信、把素材接进游戏由 Claude 做
- Claude 和 GPT 的合作只限于《苏七镇奇缘》这一款游戏的开发，不碰阿鱼的其他项目、文件和账号
- GPT 只在「苏七镇奇缘 -gpt 总文件夹」里写文件；Claude 只在「苏七镇奇缘-claude 总文件」里写文件
- 两边通过文件交接，不靠聊天转述：素材规格看这份约定，进度看 claude 文件夹里的 HANDOFF.md
- 这份约定是唯一的素材接口规则。GPT 想改，经阿鱼提出，Claude 改完升版本号

## 0. 不要出的东西

| 不要 | 原因 |
| --- | --- |
| 整张场景背景图、可走区域遮罩、遮挡层 | 只对 HD-2D 场景：3D 模型用不上。分层场景要的正是这些，见第 14 节 |
| 阿鱼、Toretto、阿晓的任何形象 | 只能用现有原图，美术包 0.1 |
| 带中文字的图，包括招牌、牌匾、对联、"囍"以外的字 | 生图模型写中文常出错；字由引擎渲染，素材只画空白底板 |
| 画死在图里的光影和投影 | 光和影子由引擎实时算。素材只画固有色和少量体积明暗 |
| 品牌 logo、真人相似、樱桃小丸子元素 | 美术包 0.1 |

## 2. 贴图 textures

| 项 | 规格 |
| --- | --- |
| 尺寸 | 32×32 或 64×64，最大 128×128，边长必须是 2 的幂 |
| 像素密度 | 16 像素 = 1 米。32×32 的贴图铺满 2 米 × 2 米 |
| 无缝 | 上下左右都能无缝拼接 |
| 格式 | PNG，不透明 |
| 色数 | 不超过 24 色，取美术包 1.2 的调色板 |

第一批，罗曼山庄宴会厅要用：

| 文件 | 内容 |
| --- | --- |
| tex_floor_wood | 木地板 |
| tex_carpet_red | 红毯，竖向可重复，左右两边是金边 |
| tex_cloth_red | 红桌布 |
| tex_wall_red | 红墙 |
| tex_drape_red | 红帷幔，竖条纹 |
| tex_lattice | 木格窗，窗纸米色 |
| tex_gold | 金饰 |

第二批，镇上要用：tex_tile_roof 小青瓦、tex_plaster 白墙、tex_timber 穿斗木架、tex_stone_slab 青石板、tex_dirt 土路、tex_grass 草地、tex_water 河水。

## 3. 角色图集 characters

| 项 | 规格 |
| --- | --- |
| 单格 | 48×64 像素，脚底对齐格底，美术包 1.3 |
| 头身比 | 按现有阿鱼立绘实测，美术包 0.2 规定以现有素材为准 |
| 排列 | 一行 16 格：下 0～3、左 4～7、右 8～11、上 12～15 |
| 背景 | 透明，alpha 只有 0 和 255 |
| 描边 | 深色描边，粗细和既有形象一致 |

同名 json：

```json
{
  "frame": [48, 64],
  "frames": { "down": [0, 1, 2, 3], "left": [4, 5, 6, 7], "right": [8, 9, 10, 11], "up": [12, 13, 14, 15] },
  "fps": 8,
  "height_m": 1.75
}
```

`height_m` 是这个角色在游戏里站着有多高，单位米。

第一批：
- `chr_guest01` 到 `chr_guest08`：按美术包 3.1 的 8 个宾客描述，一张图里一次生成 8 个，再拆开
- `chr_luoluo`、`chr_tiantian`、`chr_qiuqiu`、`chr_xiduo`：三只猫和柯基喜多。json 里用 `"walk"` 列走路帧，`"idle"` 列趴、坐、睡的帧，可以不排满 16 格

| 尺寸 | 16 像素 = 1 米，同贴图 |

第一批，宴会桌和门口的装饰：一盘菜、一个酒杯、喜糖盒、花篮、盆栽。

桌子、椅子、柱子、灯笼这类大件由代码建模，不用出图。

## 6. 场景配置 scenes

坐标单位是米。x 向右，z 朝镜头也就是向南。以罗曼山庄宴会厅为例：原点在红毯中线上，舞台前沿在 z = -16.4，门口在 z = 3.7。

```json
{
  "id": "scene_roman_banquet",
  "objects": [
    { "asset": "prop_flower_basket", "x": -3.2, "z": -15.8, "rot": 0, "scale": 1.0 }
  ],
  "points": [
    { "id": "couple_table", "x": 0.0, "z": -15.4, "r": 1.7, "kind": "talk", "line": "table" },
    { "id": "door", "x": 0.0, "z": 3.0, "r": 1.5, "kind": "door", "line": "leave" }
  ]
}
```

- `points` 是交互点：走进半径 `r` 就触发
- `line` 只写对白的 key。对白正文不写在配置里，由 Claude 按设计文档接上

## 7. 交付前自检

沿用美术包 4.3：

- 放大后像素是方的，硬边，没有半透明毛边
- 单张不超过 24 色，都在调色板里
- 透明图的 alpha 只有 0 和 255
- 和现有阿鱼立绘放在一起比，头身比、描边、色温一致
- 没有品牌 logo、真实机构名、版权角色、真人相似

## 8. Claude 这边怎么接

- 从「素材交付」读取，自动做美术包 2.3 的像素修正：最近邻缩到目标尺寸、颜色量化到调色板、alpha 二值化
- 修正后拷进 godot 工程，Godot 读到就换掉代码生成的占位；读不到就继续用占位，游戏不会坏
- 角色图集按 json 里的格子读，所以帧大小以后要改也只改 json
- 场景配置里的坐标，Claude 在 Godot 里对一遍再接上

## 9. 文案怎么交付

新写的文案放进「素材交付/copy/」，一个场景一个 json：

```json
{
  "scene": "scene_roman_banquet",
  "lines": [
    { "key": "table", "who": "阿鱼", "text": "想跟我们说点什么 写这儿 只有我们看得到", "source": "阶段 1 设计 v1.0 第 4 节" }
  ]
}
```

- `key` 和场景配置里交互点的 `line` 对应
- 设计文档里已有的对白直接引用，`source` 写出处；新写的 `source` 填"新写"，要阿鱼确认后才进游戏
- 口吻按《文案改写版 v2》：短、白描、短语末尾不打句号，不用系统口吻
- 方言按《乐山话 · 文案用法与词表》：一段话最多一个方言词，操作提示和系统提示不用方言
- 月老庙相关的文字不出现相亲、交友、单身、脱单、匹配、CP、征婚
- 不新增人物、事件、时间、地点这类故事事实

## 10. 一个场景交接一次

为了省两边的额度：每个场景 GPT 交一次，Claude 回一次，中间不靠聊天转述。

GPT 交付时，在「素材交付」根目录放一张交接单 `handoff_<场景 id>.json`，这就是开发精简包：

```json
{
  "scene": "scene_roman_banquet",
  "batch": "A01",
  "files": [
    "textures/tex_floor_wood.png",
    "characters/chr_guest03.png",
    "characters/chr_guest03.json",
    "scenes/scene_roman_banquet.json",
    "copy/scene_roman_banquet.json"
  ],
  "questions": []
}
```

- `files` 只列这次新交或改过的文件，路径相对「素材交付」
- 出图提示词、生成过程、废稿不放进来，留在 GPT 自己的完整资产包里
- 有需要 Claude 回答的，写进 `questions`，一条一句
- Claude 只读交接单里列出的文件，接完在 claude 文件夹写一份回执 `godot/回执/<batch>.md`，只写三样：改了哪些文件、交互点坐标有没有调整、要阿鱼确认的问题

## 11. 贴位积木（A02 起）

A01 的积木是花纹和小摆件，效果图里的椅子、桌面、灯罩、挂画都没有积木，只能 Claude 用方块顶着。从 A02 起，积木按「贴在哪个位置」出：Claude 用 3D 体块搭出桌子、椅子、灯笼、墙，你画的图贴到指定的那个面上。

| 贴在哪 | 怎么画 | 例 |
| --- | --- | --- |
| 水平面：地面、桌面、地毯、台面 | 纯俯视正投影：像从正上方拍的照片，不画透视、不画斜面 | tex_floor_stone、decal_tabletop、decal_rug |
| 竖直面：椅背、灯罩四面、墙上挂画 | 纯正面正投影：正对着拍，不画侧面、不画透视 | tex_chair_back、tex_lantern_panel、decal_moon_painting |
| 立在地上的纸片道具 | 略带俯视的正面，和风格锚点里的道具一样；配 json 写 height_m | prop_vase_flowers |

- 透视由游戏镜头来做：镜头从南往北、斜上方约 50° 往下看，还能左右转 45°。图里画了透视，贴上去会歪
- 可以重复铺的（地面、台面）要无缝，边长是 2 的幂，尺寸和像素密度照第 2 节
- 只贴一次的贴片（桌面、地毯、挂画）不要求无缝、不要求 2 的幂；圆形的画满画布，圆外透明。尺寸以任务卡为准
- 镂空的地方（椅背雕花的孔）用透明表示
- 光影照第 0 节：只画固有色和少量体积明暗，不画投影和反光

## 12. 拼装预览必须用积木拼

- 给阿鱼审「堆叠效果」的拼装预览，必须用这一批实际交付的积木图拼出来：可以缩放、摆位、做简单的透视变形，但不能另外重新画一张
- 另外画的氛围图、效果图，文件名和画面上都标「概念图」
- 拼装预览存 `reference/assembled_<批次>_v<版本>.png`，不进游戏
- 为什么：A01 的「拼装完成预览图」是另外画的，阿鱼以为积木拼起来就是那样；接进游戏后才发现积木里根本没有椅子、灯笼、挂画，差距很大

## 14. 分层场景（积木拼场景）

一张空的底图**或一组瓦片**，加一套能重复用的积木，配置文件写清楚每块积木摆在哪。地面、墙、红毯优先瓦片：包体只存一小块图，场景要多大铺多大；base.png 只用于瓦片拼不出的整体（舞台、背景幕）。画布可以比一屏高，镜头上下左右跟人（v1.0）。GPT 用统一脚本按配置拼出预览给阿鱼审；Claude 在游戏里照同一份配置摆，所以游戏画面和预览一模一样。人走到积木后面会被挡住，镜头不转，只跟着人移动。完整要求和脚本见任务卡 A04（`godot/docs/任务卡-A04-宴会厅新风格场景积木.md`），这里只列硬规定。

放在该画布的「积木」文件夹里（v0.9 起，例：`游戏制作中-gpt 和 claude 合作/地图一-苏七镇/罗曼山庄/001-宴会厅/积木/`），同一批文件用同一个版本号，写在 scene.json 的 revision 里：

| 文件 | 要求 |
| --- | --- |
| `base.png` | 空场景：地面、墙、舞台这些人不会走到它后面的东西。尺寸按任务卡（宴会厅 1536×1024） |
| `blk_<名字>.png` | 积木：人会走到它后面的东西，一种一张，透明底、贴边裁。同一件东西摆几次都用这一张，镜像在配置里写 |
| `fg_<名字>.png` | 前景：总画在人前面的东西，可以没有 |
| `scene.json` | 画布、人高、每种积木的脚点和占地、每次摆放的位置、能走的范围、进场点、新人位置、交互点 |
